# BlockStreet 协议清算机制详细文档

## 概述

清算是 DeFi 借贷协议中的核心风险管理机制。当借款人的抵押品价值下降，导致其健康因子低于清算阈值时，任何人都可以通过偿还部分债务来获得借款人的抵押品，从而维护协议的偿付能力。

本文档详细介绍 BlockStreet 协议的清算机制，包括：
- 如何检查哪些仓位可以被清算
- 如何执行清算操作
- A/B 代币分离模式下的特殊清算规则

## 1. 清算条件检查

### 1.1 传统模式下的清算条件

在传统模式（`separationModeEnabled = false`）下，清算条件非常简单：

```solidity
// 检查账户流动性
(Error err, uint liquidity, uint shortfall) = getAccountLiquidityInternal(borrower);

// 如果 shortfall > 0，则可以被清算
if (shortfall > 0) {
    // 可以清算
}
```

**核心概念：**
- **Liquidity（流动性）**: 账户的剩余借贷能力，表示还能借多少资金
- **Shortfall（不足额）**: 账户的流动性缺口，表示超额借贷了多少资金
- **清算条件**: `shortfall > 0` 时可以被清算

### 1.2 A/B 分离模式下的清算条件

在 A/B 分离模式（`separationModeEnabled = true`）下，清算逻辑更加复杂：

```solidity
// 获取 A/B 分离的流动性信息
(uint err, uint liquidityA, uint shortfallA, uint liquidityB, uint shortfallB) = 
    getAccountLiquiditySeparated(borrower);

// 根据借贷的代币类型检查对应的不足额
TokenType borrowedTokenType = tokenTypes[bTokenBorrowed];

uint relevantShortfall = 0;
if (borrowedTokenType == TokenType.TYPE_A) {
    relevantShortfall = shortfallB; // Type A 借贷需要 Type B 抵押品
} else if (borrowedTokenType == TokenType.TYPE_B) {
    relevantShortfall = shortfallA; // Type B 借贷需要 Type A 抵押品
}

// 如果对应类型有不足额，则可以清算
if (relevantShortfall > 0) {
    // 可以清算
}
```

**A/B 分离模式核心规则：**
- Type A 抵押品 → 只能借 Type B 代币
- Type B 抵押品 → 只能借 Type A 代币
- 清算时检查对应类型的 shortfall
- 未分类代币在分离模式下不参与借贷

## 2. 流动性计算方法

> **重要提示**: 本节介绍的都是 `public` 方法，可以被外部合约和前端直接调用。协议内部使用了对应的 `internal` 方法进行实际计算。

### 核心概念说明

在理解流动性计算前，需要理解以下关键概念：

1. **bToken数量**: 用户持有的 bToken 代币数量（如 bUSDT、bETH）
2. **交换率 (Exchange Rate)**: bToken 与底层资产的兑换比例
   - 公式: `(totalCash + totalBorrows - totalReserves) / totalSupply`
   - 作用: 将 bToken 转换为等价的底层资产数量
   - 例如: 1 bUSDT = 1.05 USDT（考虑了利息收益）

3. **抵押因子 (Collateral Factor)**: 风险控制参数
   - 范围: 0-90%（如 0.75 = 75%）
   - 作用: 限制可借贷金额，防止过度借贷
   - 例如: USDT 抵押因子 75%，存入 $100 只能借 $75

4. **底层资产价格 (Oracle Price)**: 预言机提供的资产价格
   - 来源: 价格预言机（如 Chainlink）
   - 用途: 将不同资产统一换算为价值

**计算公式：**
```
总抵押价值 = Σ(bToken数量 × 交换率 × 底层资产价格 × 抵押因子)
总借贷价值 = Σ(借贷数量 × 底层资产价格)

其中：
- bToken数量: 用户持有的 bToken 代币数量
- 交换率: bToken 与底层资产的兑换比例 (exchangeRate)
- 底层资产价格: 预言机提供的价格 (oraclePrice)  
- 抵押因子: 风险参数，决定可借贷比例 (collateralFactor)

if (总抵押价值 >= 总借贷价值) {
    liquidity = 总抵押价值 - 总借贷价值
    shortfall = 0
} else {
    liquidity = 0
    shortfall = 总借贷价值 - 总抵押价值
}
```

```solidity
}
```

**分离模式计算公式：**
```
Type A 抵押价值 = Σ(Type A bToken数量 × 交换率 × 底层资产价格 × 抵押因子)
Type B 抵押价值 = Σ(Type B bToken数量 × 交换率 × 底层资产价格 × 抵押因子)
Type A 借贷价值 = Σ(Type A 借贷数量 × 底层资产价格)
Type B 借贷价值 = Σ(Type B 借贷数量 × 底层资产价格)

// 交叉计算流动性
Type A 流动性 = Type A 抵押价值 vs Type B 借贷价值
Type B 流动性 = Type B 抵押价值 vs Type A 借贷价值
```

### 流动性计算示例

**假设用户账户状况：**
- 持有 100 bUSDT，交换率 1.05，USDT价格 $1，抵押因子 75%
- 持有 1 bETH，交换率 1.02，ETH价格 $2000，抵押因子 80%  
- 借贷 50 USDT，USDT价格 $1
- 借贷 0.5 ETH，ETH价格 $2000

**计算过程：**
```
USDT抵押价值 = 100 × 1.05 × $1 × 0.75 = $78.75
ETH抵押价值 = 1 × 1.02 × $2000 × 0.80 = $1,632
总抵押价值 = $78.75 + $1,632 = $1,710.75

USDT借贷价值 = 50 × $1 = $50  
ETH借贷价值 = 0.5 × $2000 = $1,000
总借贷价值 = $50 + $1,000 = $1,050

流动性 = $1,710.75 - $1,050 = $660.75 > 0 (健康)
不足额 = 0
```

该账户健康状况良好，**不能被清算**。

## 3. 检查可清算仓位的实用方法

### 3.1 单个账户检查

```javascript
// 检查单个账户是否可清算（JavaScript/Web3 示例）
async function checkLiquidatable(accountAddress) {
    const blotroller = new web3.eth.Contract(BlotrollerABI, blotrollerAddress);
    
    // 检查是否启用分离模式
    const separationMode = await blotroller.methods.separationModeEnabled().call();
    
    if (separationMode) {
        // A/B 分离模式
        const result = await blotroller.methods.getAccountLiquiditySeparated(accountAddress).call();
        const [error, liquidityA, shortfallA, liquidityB, shortfallB] = result;
        
        console.log(`账户 ${accountAddress}:`);
        console.log(`Type A - 流动性: ${liquidityA}, 不足额: ${shortfallA}`);
        console.log(`Type B - 流动性: ${liquidityB}, 不足额: ${shortfallB}`);
        
        return {
            canLiquidateA: shortfallA > 0,
            canLiquidateB: shortfallB > 0,
            shortfallA: shortfallA,
            shortfallB: shortfallB
        };
    } else {
        // 传统模式
        const result = await blotroller.methods.getAccountLiquidity(accountAddress).call();
        const [error, liquidity, shortfall] = result;
        
        console.log(`账户 ${accountAddress}: 流动性: ${liquidity}, 不足额: ${shortfall}`);
        
        return {
            canLiquidate: shortfall > 0,
            shortfall: shortfall
        };
    }
}
```

### 3.2 批量检查

```javascript
// 批量检查多个账户
async function batchCheckLiquidatable(accounts) {
    const liquidatableAccounts = [];
    
    for (const account of accounts) {
        try {
            const result = await checkLiquidatable(account);
            if (result.canLiquidate || result.canLiquidateA || result.canLiquidateB) {
                liquidatableAccounts.push({
                    account: account,
                    ...result
                });
            }
        } catch (error) {
            console.error(`检查账户 ${account} 时出错:`, error);
        }
    }
    
    return liquidatableAccounts;
}
```

## 4. 清算执行

### 4.1 清算参数说明

执行清算前需要了解以下关键参数：

1. **Close Factor（关闭因子）**: 限制单次清算的最大偿还比例, 当前我们是50%
   - 范围：5% - 90%（0.05e18 - 0.9e18）
   - 计算：`maxRepay = borrowBalance × closeFactor`

2. **Liquidation Incentive（清算激励）**: 清算者获得的折扣
   - 例如：1.08e18 表示 8% 的清算奖励
   - 计算：`seizeAmount = repayAmount × liquidationIncentive × priceBorrowed / priceCollateral`

### 4.2 ERC20 代币清算

```solidity
// 清算 ERC20 代币
function liquidateBorrow(
    address borrower,           // 被清算的借款人
    uint repayAmount,          // 偿还的借贷代币数量
    BTokenInterface bTokenCollateral  // 要获得的抵押品 bToken
) external returns (uint)
```

**示例代码：**
```javascript
async function liquidateERC20(borrowerAddress, borrowedToken, collateralToken, repayAmount) {
    const bToken = new web3.eth.Contract(BTokenABI, borrowedToken);
    
    // 1. 检查清算是否被允许
    const allowed = await blotroller.methods.liquidateBorrowAllowed(
        borrowedToken,
        collateralToken,
        liquidatorAddress,
        borrowerAddress,
        repayAmount
    ).call();
    
    if (allowed !== '0') {
        throw new Error(`清算不被允许，错误代码: ${allowed}`);
    }
    
    // 2. 计算将获得的抵押品数量
    const seizeResult = await blotroller.methods.liquidateCalculateSeizeTokens(
        borrowedToken,
        collateralToken,
        repayAmount
    ).call();
    
    const [error, seizeTokens] = seizeResult;
    console.log(`将获得 ${seizeTokens} 个抵押品代币`);
    
    // 3. 确保有足够的代币进行偿还
    const underlyingToken = new web3.eth.Contract(ERC20ABI, await bToken.methods.underlying().call());
    await underlyingToken.methods.approve(borrowedToken, repayAmount).send({from: liquidatorAddress});
    
    // 4. 执行清算
    const tx = await bToken.methods.liquidateBorrow(
        borrowerAddress,
        repayAmount,
        collateralToken
    ).send({from: liquidatorAddress});
    
    console.log('清算交易成功:', tx.transactionHash);
    return tx;
}
```

### 4.4 计算最优清算参数

```javascript
async function calculateOptimalLiquidation(borrowerAddress, borrowedToken, collateralToken) {
    // 1. 获取借贷余额
    const bToken = new web3.eth.Contract(BTokenABI, borrowedToken);
    const borrowBalance = await bToken.methods.borrowBalanceStored(borrowerAddress).call();
    
    // 2. 获取 close factor
    const closeFactor = await blotroller.methods.closeFactorMantissa().call();
    const maxRepay = Math.floor(borrowBalance * closeFactor / 1e18);
    
    // 3. 获取价格信息
    const oracle = new web3.eth.Contract(OracleABI, await blotroller.methods.oracle().call());
    const borrowPrice = await oracle.methods.getUnderlyingPrice(borrowedToken).call();
    const collateralPrice = await oracle.methods.getUnderlyingPrice(collateralToken).call();
    
    // 4. 计算清算激励
    const liquidationIncentive = await blotroller.methods.liquidationIncentiveMantissa().call();
    
    // 5. 计算预期收益
    const profit = maxRepay * borrowPrice * liquidationIncentive / collateralPrice / 1e18 - maxRepay * borrowPrice / 1e18;
    
    return {
        maxRepayAmount: maxRepay,
        expectedProfit: profit,
        borrowBalance: borrowBalance,
        liquidationIncentive: liquidationIncentive
    };
}
```

## 5. A/B 分离模式特殊考虑

### 5.1 分离模式下的清算规则

在 A/B 分离模式下，清算需要遵循特殊规则：

1. **借贷类型检查**: 只有 Type A 或 Type B 代币可以被清算
2. **对应性检查**: 
   - 清算 Type A 借贷时，检查 Type B 的 shortfall
   - 清算 Type B 借贷时，检查 Type A 的 shortfall
3. **抵押品限制**: 只能扣押对应类型的抵押品

### 5.2 分离模式清算示例

```javascript
async function liquidateInSeparationMode(borrowerAddress, borrowedToken) {
    // 1. 检查是否启用分离模式
    const separationMode = await blotroller.methods.separationModeEnabled().call();
    if (!separationMode) {
        throw new Error('当前不在分离模式下');
    }
    
    // 2. 获取借贷代币类型
    const borrowedTokenType = await blotroller.methods.tokenTypes(borrowedToken).call();
    
    // 3. 获取分离模式流动性
    const liquidityResult = await blotroller.methods.getAccountLiquiditySeparated(borrowerAddress).call();
    const [error, liquidityA, shortfallA, liquidityB, shortfallB] = liquidityResult;
    
    // 4. 检查是否可清算
    let canLiquidate = false;
    let relevantShortfall = 0;
    
    if (borrowedTokenType === '1') { // TYPE_A
        canLiquidate = shortfallB > 0;
        relevantShortfall = shortfallB;
        console.log('清算 Type A 借贷，需要检查 Type B shortfall:', shortfallB);
    } else if (borrowedTokenType === '2') { // TYPE_B
        canLiquidate = shortfallA > 0;
        relevantShortfall = shortfallA;
        console.log('清算 Type B 借贷，需要检查 Type A shortfall:', shortfallA);
    } else {
        throw new Error('未分类代币不能在分离模式下被清算');
    }
    
    if (!canLiquidate) {
        throw new Error('账户在分离模式下不满足清算条件');
    }
    
    // 5. 选择合适的抵押品代币（与借贷代币类型相对应）
    const assets = await blotroller.methods.getAssetsIn(borrowerAddress).call();
    let suitableCollateral = null;
    
    for (const asset of assets) {
        const assetType = await blotroller.methods.tokenTypes(asset).call();
        // 选择与借贷代币类型相对应的抵押品
        if ((borrowedTokenType === '1' && assetType === '2') || 
            (borrowedTokenType === '2' && assetType === '1')) {
            
            const collateralBalance = await new web3.eth.Contract(BTokenABI, asset).methods.balanceOf(borrowerAddress).call();
            if (collateralBalance > 0) {
                suitableCollateral = asset;
                break;
            }
        }
    }
    
    if (!suitableCollateral) {
        throw new Error('没有找到合适的抵押品进行清算');
    }
    
    // 6. 执行清算
    return await liquidateERC20(borrowerAddress, borrowedToken, suitableCollateral, maxRepayAmount);
}
```

## 6. 风险控制和最佳实践

### 6.1 清算前检查清单

1. **流动性验证**: 确认账户确实存在 shortfall
2. **市场状态**: 检查相关市场是否正常运行（未暂停）
3. **价格检查**: 确认价格预言机正常工作
4. **余额检查**: 确保清算者有足够代币进行偿还
5. **Gas 费估算**: 计算交易成本，确保有利可图
6. **滑点保护**: 考虑价格变动对清算的影响

### 6.2 错误处理

```javascript
async function safeLiquidate(borrowerAddress, borrowedToken, collateralToken, repayAmount) {
    try {
        // 1. 预检查
        const liquidityCheck = await checkLiquidatable(borrowerAddress);
        if (!liquidityCheck.canLiquidate) {
            throw new Error('账户不满足清算条件');
        }
        
        // 2. 模拟交易
        const gasEstimate = await bToken.methods.liquidateBorrow(
            borrowerAddress, repayAmount, collateralToken
        ).estimateGas({from: liquidatorAddress});
        
        // 3. 执行清算
        const tx = await liquidateERC20(borrowerAddress, borrowedToken, collateralToken, repayAmount);
        
        return {success: true, tx: tx};
        
    } catch (error) {
        console.error('清算失败:', error.message);
        
        // 常见错误处理
        if (error.message.includes('INSUFFICIENT_SHORTFALL')) {
            return {success: false, reason: '账户流动性充足，无需清算'};
        } else if (error.message.includes('LIQUIDATE_SEIZE_TOO_MUCH')) {
            return {success: false, reason: '清算数量过大，超过抵押品余额'};
        } else if (error.message.includes('LIQUIDATE_CLOSE_AMOUNT_TOO_HIGH')) {
            return {success: false, reason: '偿还数量超过 close factor 限制'};
        }
        
        return {success: false, reason: error.message};
    }
}
```

## 7. 总结

BlockStreet 协议的清算机制具有以下特点：

1. **双模式支持**: 支持传统模式和 A/B 分离模式
2. **风险隔离**: A/B 分离模式实现了不同资产类型的风险隔离
3. **激励机制**: 通过清算奖励激励清算者维护协议安全
4. **灵活配置**: 管理员可以调整 close factor 和 liquidation incentive

### 清算流程总结：

1. **监控**: 持续监控账户流动性状态
2. **检查**: 发现 shortfall > 0 的账户
3. **计算**: 确定最优清算参数
4. **执行**: 调用相应的清算函数
5. **验证**: 确认清算结果和收益

通过本文档的指导，开发者可以构建完整的清算机器人系统，为 BlockStreet 协议的安全稳定运行做出贡献。
